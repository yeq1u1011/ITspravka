nmtui и nmcli — настройка сети
NetworkManager · интерфейсы · IP-адреса
›

nmtui — текстовый интерфейс (TUI) для NetworkManager. Позволяет настроить IP, маску, шлюз и DNS без редактирования файлов вручную. Запускается командой nmtui.

nmcli — консольный инструмент, удобен для скриптов и быстрых изменений. Показывает статус соединений, активирует/деактивирует интерфейсы.

nmtui — разделы меню «Изменить соединение» → выбрать интерфейс → IPv4 Config → Manual → указать Address, Gateway, DNS. После сохранения — «Активировать соединение».
bash — nmcli
# === Просмотр состояния === nmcli device status # список интерфейсов nmcli con show # список соединений ip addr show # текущие IP-адреса ip route show # таблица маршрутов # === Управление соединениями === nmcli con up "ens18" # активировать соединение nmcli con down "ens18" # деактивировать nmcli con reload # перечитать конфиги # === Статический IP вручную === nmcli con mod "ens18" ipv4.method manual \ ipv4.addresses "192.168.1.10/24" \ ipv4.gateway "192.168.1.1" \ ipv4.dns "8.8.8.8,1.1.1.1" nmcli con up "ens18"
⚠️ ALT Linux — важно В ALT Linux файлы конфигурации сети лежат в /etc/net/ifaces/ens18/. Файл options содержит BOOTPROTO, файл ipv4address — адрес.

VLAN — виртуальные сети
tagged / untagged · trunk · access
›

VLAN (Virtual LAN) позволяет логически разделить сеть на сегменты поверх одного физического интерфейса. В Linux используется через ip link или файлы конфигурации NetworkManager.

Access-портОдин VLAN, трафик без тега. Для конечных устройств.
Trunk-портНесколько VLAN, трафик с тегами 802.1Q. Между коммутаторами/роутерами.
bash
# Создать VLAN-интерфейс (VLAN ID 10 на ens18) ip link add link ens18 name ens18.10 type vlan id 10 ip addr add 192.168.10.1/24 dev ens18.10 ip link set ens18.10 up # Проверить ip link show type vlan cat /proc/net/vlan/config

DNS и DHCP — адресация в сети
bind9 · isc-dhcp-server · resolv.conf
›

DNS (Domain Name System) — переводит доменные имена в IP-адреса. Сервер bind9 настраивается через зональные файлы.

DHCP автоматически раздаёт IP-адреса клиентам. Сервер isc-dhcp-server — классический вариант для Linux.

Основные файлы bind9:

/etc/bind/named.conf.localОписание зон (zone "example.local")
/etc/bind/named.conf.optionsФорвардеры, ACL, общие параметры
/etc/bind/db.exampleФайл зоны (A, NS, MX, PTR записи)
bash — проверка DNS
named-checkconf # проверить конфиг named-checkzone example.local /etc/bind/db.example systemctl restart bind9 dig @127.0.0.1 server01.example.local nslookup server01 127.0.0.1
bash — проверка DHCP
systemctl restart isc-dhcp-server journalctl -u isc-dhcp-server -f cat /var/lib/dhcp/dhcpd.leases # выданные аренды
⚠️ Частая ошибка В /etc/default/isc-dhcp-server обязательно нужно прописать INTERFACESv4="ens18" — иначе служба не стартует.

Маршрутизация — статика и основы
ip route · forwarding · шлюз
›

Маршрутизация определяет, по какому пути пакеты покидают систему. Статические маршруты прописываются вручную и не изменяются автоматически.

bash
ip route show # текущая таблица маршрутов ip route add 10.0.0.0/8 via 192.168.1.1 # добавить маршрут ip route del 10.0.0.0/8 # удалить маршрут ip route add default via 192.168.1.1 # маршрут по умолчанию # Включить IP-форвардинг (для роутера) echo 1 > /proc/sys/net/ipv4/ip_forward # Постоянно — добавить в /etc/sysctl.conf: # net.ipv4.ip_forward = 1
Безопасность и доступ

SSH — удалённый доступ
ключи · sshd_config · подключение
›

SSH (Secure Shell) — протокол для защищённого удалённого управления сервером. Настройка ведётся в файле /etc/ssh/sshd_config.

Аутентификация по ключу Генерируешь пару ключей на клиенте. Публичный ключ копируешь на сервер в ~/.ssh/authorized_keys. После этого пароль при входе не нужен.
bash
# Генерация ключей (на клиенте) ssh-keygen -t ed25519 -C "mykey" # Копировать публичный ключ на сервер ssh-copy-id user@192.168.1.10 # Подключение по ключу ssh -i ~/.ssh/id_ed25519 user@192.168.1.10 # Важные параметры /etc/ssh/sshd_config # PasswordAuthentication no ← отключить пароли # PermitRootLogin no ← запретить root # PubkeyAuthentication yes ← включить ключи # Port 22 ← порт (можно сменить) systemctl restart sshd ss -tlnp | grep sshd # проверить порт

Firewall — iptables и ufw
правила · цепочки · NAT · фильтрация
›

iptables — низкоуровневый файрволл Linux. Работает с цепочками INPUT, OUTPUT, FORWARD. ufw — упрощённая обёртка над iptables для повседневного использования.

Цепочка INPUTПакеты, входящие на сам сервер.
Цепочка FORWARDПакеты, проходящие через сервер (роутинг).
Цепочка OUTPUTПакеты, исходящие от сервера.
Цепочка POSTROUTINGNAT — подмена адреса на выходе.
bash — ufw
ufw status verbose ufw enable ufw default deny incoming ufw default allow outgoing ufw allow 22/tcp ufw allow 80/tcp ufw allow 443/tcp ufw allow from 192.168.1.0/24 to any port 3306 ufw delete allow 80/tcp ufw reload
bash — iptables
iptables -L -n -v --line-numbers # просмотр правил iptables -A INPUT -p tcp --dport 22 -j ACCEPT iptables -A INPUT -m state --state ESTABLISHED -j ACCEPT iptables -P INPUT DROP # политика по умолчанию # NAT (маскарад — выход в интернет через сервер) iptables -t nat -A POSTROUTING -o ens18 -j MASQUERADE # Сохранить правила (ALT Linux) iptables-save > /etc/sysconfig/iptables

Пользователи и права доступа
useradd · группы · sudo · chmod · chown
›

Управление пользователями — одна из базовых задач администратора. В ALT Linux для добавления пользователей можно использовать useradd или adduser (интерактивный).

bash
# Создать пользователя с домашней директорией useradd -m -s /bin/bash alice passwd alice # Группы groupadd devteam usermod -aG devteam alice usermod -aG wheel alice # добавить в sudo (ALT Linux) # Проверка id alice groups alice # Права на директорию chown -R alice:devteam /srv/project chmod 770 /srv/project # rwxrwx--- chmod 755 /srv/www # rwxr-xr-x # sudo — отредактировать через visudo # alice ALL=(ALL) NOPASSWD:ALL
ALT Linux — группа wheel В ALT Linux пользователи, которым нужен sudo, добавляются в группу wheel, а не sudo как в Debian/Ubuntu.

systemd — управление службами
systemctl · journalctl · unit-файлы
›

systemd — система инициализации в современных дистрибутивах Linux, включая ALT. Управляет запуском служб, монтированием, таймерами.

systemctl start nginxЗапустить службу
systemctl stop nginxОстановить службу
systemctl restart nginxПерезапустить
systemctl reload nginxПеречитать конфиг без остановки
systemctl enable nginxАвтозапуск при загрузке
systemctl disable nginxУбрать из автозапуска
systemctl status nginxСтатус и последние логи
systemctl list-units --failedУпавшие службы
bash — journalctl
journalctl -u nginx -f # логи службы в реальном времени journalctl -xe # ошибки системы journalctl --since "1 hour ago" journalctl -b # логи с последней загрузки journalctl -p err # только ошибки

Управление пакетами — apt-get / apt
установка · удаление · репозитории
›

В ALT Linux используется пакетный менеджер apt-get и apt-rpm. Репозитории прописаны в /etc/apt/sources.list.d/.

bash
apt-get update # обновить список пакетов apt-get upgrade # обновить установленные apt-get install nginx # установить пакет apt-get remove nginx # удалить пакет apt-get autoremove # удалить лишние зависимости apt-cache search nginx # поиск пакета apt-cache show nginx # информация о пакете rpm -qa | grep nginx # проверить установку (RPM) rpm -ql nginx # список файлов пакета
ALT Linux — особенность В отличие от Debian/Ubuntu, ALT Linux основан на RPM-пакетах, но использует APT как фронтенд. Команды похожи, но пакеты в формате .rpm.
